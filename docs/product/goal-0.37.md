# Goal · 0.37

> 来源：2026-11-05 用户在 Windows 上实测 0.36.0 后的反馈。这一版做完直接提交、推送、发版，不再中途确认；最后汇报完成情况，并回答下面「要回答的疑问」。

## 要做的事

### 1. exe 没有图标
- Windows exe 嵌入图标资源（任务栏、资源管理器、桌面快捷方式都要有），同时给窗口本身设置图标（eframe `ViewportBuilder::with_icon`）。
- 图标从 `packaging/linux/` 现有的 SVG/PNG 生成 `.ico`（16–256 多尺寸），提交进仓库，构建时不依赖额外工具；Linux 窗口图标也用同一套。
- 顺带写好 exe 的版本信息资源（产品名、公司/作者、文件说明、版本号）。
- 验证：交叉编译 Windows 目标通过；Release 产物下载回来用工具确认图标和版本资源确实在 exe 里。

### 2. 下载时的安全警告
- 浏览器提示「通常不会下载 xxx.exe，请在打开前确保信任」，而 HMCL 不会。研究原因（SmartScreen 下载信誉、代码签名、下载量、文件类型等），以及 HMCL 实际是怎么发布的。
- 做能做的：不需要用户花钱或提供凭据的改进直接做（例如版本资源、发布形式）；需要证书的（代码签名、Azure Trusted Signing 之类）在 CI 里预留好，没配置密钥时自动跳过，并在汇报里说清楚用户要做什么、要花多少钱。

### 3. 文字处理
- 启动台的版本名不能截成「新：模拟大都…」：按宽度自动缩小字号，必要时两行，保证完整显示；比例要好看。
- 设置里「游戏目录」标签和长路径重叠（Windows 实测）：修好，长路径中间省略、悬停看全路径、可复制。
- 全面检查一遍长文本：版本名、整合包名、路径、Mod 名、错误提示，在 900×620 和中文/英文混排下都不重叠、不截断关键信息。

### 4. 启动参数在启动前就看得见、改得了
- 现在参数要启动之后才在日志里看到。启动台要直观地展示这次会怎么启动：Java（哪个、为什么选它）、内存、回收器、额外 JVM 参数、窗口大小，以及完整的命令行预览（可复制）。
- **按版本配置**：Java 可选（自动 / 本机检测到的任一个 / 手动指定路径），内存、回收器、JVM 参数、窗口大小都可以按版本覆盖全局设置；没改的跟随全局，并标明来源。
- core 的 `LaunchOptions` 支持指定 Java 路径；不兼容的 Java（版本太低）要提前提示。

### 5. 内容 › 已安装 秒开
- 现在每次进页面都要扫描一会儿。用缓存：先立刻显示上次的索引，再在后台校验；只有文件名、大小、修改时间变了的文件才重新读压缩包。
- 实时性：启动器自己做的增删改启停立刻更新缓存；外部改动靠目录签名发现（已有回到窗口自动重扫）。不能出现列表和磁盘不一致还看不出来的情况。写测试覆盖。

### 6. 启动台的截图墙
- 像 Steam 游戏页下方的截图那样：读当前版本游戏目录的 `screenshots/`，在启动台下方显示缩略图条，最新的在前。
- 左键打开（大图预览或系统看图），右键直接把图片复制到剪贴板（图片本身，不是路径），给明确的反馈。
- 缩略图后台解码、缩小、缓存到磁盘（按路径 + 修改时间），不卡界面、空闲 CPU 仍为 0。
- 动效要设计好：悬停、加载淡入、复制成功的反馈、打开时的过渡；尊重「减少动效」设置。没有截图时给一个不碍事的空状态（告诉玩家 F2 截图）。

### 7. 改名
- 起一个好名字替换 nailong（名字不是「奶龙」的意思，风格要简洁、哑光、高级，不像 Minecraft 官方启动器，也不要可爱化）。注意避开已有的知名软件和商标。
- 改显示名、窗口标题、exe/deb 名、桌面文件、metainfo、README、文档。
- 老用户的数据目录（`~/.local/share/nailong`、`%APPDATA%\nailong` 等）要自动迁移或兼容，配置和存档一个都不能丢；deb 能从旧包平滑升级。
- GitHub 仓库名不在这里改（对外链接会变），在汇报里告诉用户怎么改、改了有什么影响。

- 每项都要实测：Xvfb 截图（深浅两种、1120×720 和 900×620）、单元测试、fmt、clippy（Linux 和 Windows 目标）。
