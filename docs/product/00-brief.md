# nailong 产品 brief

> 状态：0.25。所有界面与功能取舍先回到这一页，再谈实现。

## 1. 一句话

**装得干净，坏了能救。**

不是“功能最多的启动器”，而是让玩家敢把整合包、Mod 和存档交给它，并且知道出问题时能退回去。

## 2. 玩家

- 主要：玩 1.16–1.21 的普通玩家，会装整合包和几十个 Mod，但不想读日志。
- 现在不服务：从 PCL2 / HMCL / 官方启动器整目录迁移的人。nailong 还没正式发布，不为旧 `.minecraft` 兼容付成本。
- 还不是：服主、Mod 开发者、需要多实例 CI 的重度用户。

## 3. 现在的真问题

1. **第一次可能进不去**：Java 要预装，Windows 没有实机验证；登录链接、页面切换和错误提示是玩家最先碰到的门槛。
2. **坏了只能重装**：存档有快照，但 Mod、配置、加载器没有实例级回滚。
3. **首页像控制台**：账户、内存、路径、统计、日志和启动抢注意力。
4. **工程语言太多**：版本 ID、隔离、快照、仓库、块、processor，玩家不知道要不要点。
5. **没有一句话的差异**：轻量/ Rust / 单文件是工程优势，不是玩家换启动器的理由。

## 4. 三个承诺

1. **第一次就能玩**：检测/引导 Java，装整合包不超过三步；不承诺导入旧启动器目录。
2. **装得干净**：内容只进当前版本，前置和冲突在安装前说清楚，不静默覆盖。
3. **坏了能救**：每次内容变更前留一个可回滚的实例快照；一键回到上一次能玩的状态。

## 5. 信息架构

始终四个一级入口，不再增加：

- **启动台**：玩。一个当前版本、一个主行动、一个最近世界；设置收起来。
- **版本**：装游戏、修游戏、看安装信息；整合包和普通版本都叫“游戏配置”。
- **内容**：发现 + 已安装；安装前确认，更新前留回滚点。
- **存档**：世界 + 备份时间线；恢复默认先保留当前世界。

设置、账户、日志、路径是工具，不是一级页面，放在侧边栏底部的「设置」里。

## 6. 非目标

- 不做社交、联机大厅、皮肤站、云同步。
- 不追求覆盖所有冷门启动器格式；先把 6 种已有格式的失败路径做可靠。
- 不做旧 `.minecraft` 整目录兼容/迁移；未正式发布前只服务新装路径。
- 不做深色主题的第二套维护成本；先把浅色一套做完整。
- 不做后台静默更新内容；更新必须可撤销。

## 7. 指标

- 首次安装 → 进入主菜单成功率。
- 从打开启动器到点击开始的时间（time-to-play）。
- 内容安装成功率 / 安装后启动成功率。
- 回滚成功率（点了“恢复”之后能进游戏的比例）。
- 崩溃/失败会话占比；错误码可检索率。
- 7 日留存与“推荐给朋友”的主观反馈。

没有这些数据之前，不用“更精致”当发布理由。

## 8. 发布门槛

- Windows 10/11 实机：安装、启动、登录、更新、卸载各一遍。
- 断网/弱网/中断安装/磁盘满/路径含中文各一遍。
- 900×620、125%/150% DPI、键盘导航、减少动效。
- 截图回归：启动台、版本、内容发现/已安装、详情、存档、进度、设置。
- 自动更新、签名、崩溃报告至少有一项闭环；没有就明确标 preview，不推荐日常使用。

## 9. 迭代顺序

1. **0.19**：产品 brief、启动台单一主行动、设置收口、设计系统 v2。已完成。
2. **0.20**：内容/配置/内容索引的实例恢复点；安装、更新、导入、删除前自动留点；恢复前安全留档。已完成，加载器二进制/版本 JSON 不在这一版范围内。
3. **0.21**：内容安装确认、首次启动引导（Java、整合包）。已完成；Windows 实机仍待补。
4. **0.22**：加载器状态恢复（版本 JSON 与补丁 jar）、重装加载器前自动留点。已完成默认实例覆盖；共享 libraries 不复制。
5. **0.23**：登录（Windows URL）、取消状态、切页卡顿、错误文案与加载态。已完成代码与 Linux 冒烟；Windows 真机待补。
6. **0.24**：登录失败结果卡、Esc 关闭、内容错误态重载。已完成代码与截图；Windows 真机仍待补。
7. **0.25**：版本页统计层级、存档/版本页开关统一。已完成。
8. **0.26**：更新确认与更新说明、性能预算、可访问性、Windows 实机。
9. 之后：内容策展、正式 1.0 评估。

## 10. 一句话验收

一个只会点“开始游戏”的玩家，和一个装 200 个 Mod 的玩家，都能在不看日志的情况下完成自己的事；坏了能退回去。
