# GUI 基线测量（2026-10）

> 目的：为 [02 技术选型](../design/02-tech-stack.md#2-gui-选型) 提供可复现的初始数据。
> 结论只用于**横向排序**；最终以 M0 的 Windows 真实 GPU 测量为准。

## 1. 环境

| 项 | 值 |
|---|---|
| OS | Linux x86_64 |
| Rust | 1.99.1 |
| 显示 | Xvfb 1280×800 |
| 渲染 | Mesa llvmpipe（软件 OpenGL/Vulkan） |
| 构建 | `opt-level="z"`, `lto="fat"`, `codegen-units=1`, `panic="abort"`, `strip=true` |
| 程序 | 显示一行中英文文本的最小窗口 |
| 启动时间 | `spawn` → `xdotool search --name hello` 成功 |
| RSS | 窗口刚出现 / 静置 4–5 s |

## 2. 结果

| 框架/配置 | 二进制 | gzip -9 | 启动到窗口 | RSS（出现） | RSS（静置） | 线程 |

| **egui 0.37 + eframe(glow)** | **5.15 MiB** | 2.11 MiB | **36–40 ms** | 71–85 MiB | 107 MiB | 34 |
| egui 0.37 默认 release（未 strip/LTO） | 8.67 MiB | — | — | — | — | — |

| iced 0.13 + wgpu + tiny-skia | 6.02 MiB | — | 98–115 ms | 155 MiB | 217 MiB | 71 |
| Slint 1.18 + femtovg | 9.72 MiB | 4.94 MiB | 88–101 ms | 85–96 MiB | 129 MiB | 38 |

## 4. 解读

1. **iced + tiny-skia 最轻**：CPU 渲染、无 GPU 驱动依赖、30 MB 级 RSS；代价是 Elm 架构样板与自定义控件成本。
2. **egui + glow 次轻**：5.15 MiB / 40 ms；107 MiB 是软件渲染上界，Windows 经验值 40–80 MB。开发效率与自绘能力最好。
3. **iced + wgpu 在软件渲染下不可用**：217 MiB；不是因为 wgpu 本身差，而是 llvmpipe 放大了缓冲。真实 GPU 上会低很多，但仍高于 tiny-skia。
4. **Slint 更重**：hello 就近 10 MiB；CJK 字体还需额外打包；许可为 GPL/商业。
5. **Tauri/gpui 不适合本项目**：WebView2 运行时/多进程内存；gpui API 不稳且发布物 53 MB。

## 5. 局限

- 只有 Linux + 软件渲染；Windows 的 DWM/GPU 驱动会改变绝对值。
- 只测空窗口；真实启动器的字体图集、图标、列表会显著增加 RSS。
- 未测长时间空闲的 CPU/耗电；egui 需要 `request_repaint_after` 纪律。
- 未测 IME 行为；需在 Windows 上人工验收。

## 6. 复现计划（M0）

1. 在 Windows 11 x64 上重复上述最小程序（egui/iced 各一）。
2. 加入 20 个假实例卡片 + 中文字体，测首帧、静置 RSS、滚动帧率。
3. 用微软拼音输入中文实例名，记录候选窗/重复字符问题。
4. 把结果回填本文件与 [02](../design/02-tech-stack.md)，并据此确认 ADR-001。
